**V1a (`v1a_probe.py`), at `a856ec2` and at `e883fa3`, with identical output.**

- **The bodies.** There are 29 raw bodies under `corpus/fixtures/zoo/`, one per
  entry of the manifests' `forwards`.
  - Each body's sha256 and length were checked against its manifest.
  - All 29 are declared `application/x-protobuf` with no coding.
- **The pure layer** (`Endpoint.handle` on a `Request` built from the
  manifest): **29 of 29** answer `Response(status=200, body=b"",
  content_type="application/x-protobuf")`. There is no event, no diagnostic and
  no skipped record, and 372 records were read.
- **On a loopback socket.** The probe drove `handler_class` over
  `http.server.BaseHTTPRequestHandler` with its own `http.client` request
  (not the tests' `Posting`/`FakeHandler`).
  - **29 of 29** answer `200`, with `Content-Type: application/x-protobuf`,
    `Content-Length: 0` and an empty body.
  - The response headers are `Server`, `Date`, `Content-Type` and
    `Content-Length`.
- **The zero bytes are the default message.**
  - `ExportTraceServiceResponse().ParseFromString(b"")` consumes 0 bytes.
  - The result `== ExportTraceServiceResponse()`, with
    `HasField("partial_success")` false, `ListFields()` `[]` and `ByteSize()`
    0.
  - The default serializes to `b""`, deterministically too. Its OTLP/JSON is
    `'{}'`, and `Parse('{}')` gives the default.
  - With an all-default `partial_success` *set*, it is `b'\n\x00'`
    (`{"partialSuccess": {}}`). So `b""` is exactly the message with
    `partial_success` unset, which OTLP's *Full Success* asks for: "The server
    MUST leave the `partial_success` field unset in case of a successful
    response."
- **The reply's type follows the declared media type and nothing else.**
  - **The table:** 12 bodies × 13 `Content-Type` values × 3 `Accept`
    values = **468 rows**, each run on the pure layer and on the socket, with
    the same answer on every row.
    - The bodies: raw Z1 and Z5, JSON Z1, empty, gzip and `GZIP` raw, gzip
      JSON, truncated raw, non-gzip declared gzip, `deflate`, brace-first bytes
      and `0x0a`-first bytes.
    - The `Content-Type` values: the protobuf type in case and parameter
      variants, the JSON type likewise, `application/protobuf`,
      `application/octet-stream`, `text/plain`, `""` and absent.
  - **Every `200`:** its type is the declared type, lowercased and without
    parameters, and its body is `{}` for JSON or `b""` for protobuf. There are
    81 JSON and 90 protobuf.
  - **Every refusal** is `application/json` with `{"code": <its one event's
    code>}`: 93 × `400 unreadable_body` and 204 × `415
    unsupported_media_type`.
  - **No other input moves the type.** `Accept` never moves anything. Raw Z1
    declared JSON is `200 {}` as JSON. JSON Z1 declared protobuf is `400` as
    JSON. A `GET`, a wrong target and `Transfer-Encoding: chunked` are each
    `415` as JSON.
- **The parent fails it.** At `fef26e0` the first assertion fails:
  `Response(status=200, body=b'{}', content_type='application/json')`.
