### (d) R5 — rotation is detected and the mechanism is portable, but **macOS CI does not cover it**. The Tail correction's *reason* is true; its wording is not.

**The test that proves rotation**, as distinct from truncation, is
`tests/test_ingest.py::test_rotation_reopens_by_path_and_loses_nothing_the_old_file_held`
— it renames the file in the same driver action as the replacement is created, so
the old inode holds unread bytes at the moment the path stops naming it, then
asserts `source.counts == {ROTATED: 1}`, `event.offset == len(first.data)`, and both
traces' graphs equal `spanweave.build`'s. Its companion
`::test_a_rotation_the_old_handle_still_owes_bytes_for_is_not_seen_yet` asserts no
`rotated` was claimed while the handle still owed bytes. Truncation's own test is
the separate `::test_truncation_restarts_from_zero_and_is_an_event`. Both mutations
(`_shrank() → False`; the inode comparison → `if True`) are caught, 2 tests each.

Mechanism: truncation is `os.fstat(handle).st_size < self._offset` on the open
handle; rotation is `path.stat()`'s `(st_dev, st_ino)` against `os.fstat`'s, checked
only on a poll that read nothing. Both are plain POSIX fields and behave identically
on Linux and macOS. **The code is portable. What is not established is that CI
proves it.** `.github/workflows/ci.yml`: the `check` job is the only job that runs
`pytest` at all and is `runs-on: ubuntu-latest` across 3.11–3.14; the `conformance`

rotation detection is a platform fact" — is a non-sequitur: the macOS job cannot see

**T1 · R3 · `Router.completion` is a mutable public field, and a completion attached
*after* records have been routed measures `Quiet` from the tick, not the records.**
`Router` is `@dataclass(slots=True, kw_only=True)` — not frozen — and `route`

happens when a policy is added mid-stream and no test covers it. Either state it in
§5.2 or make `completion` constructor-only. Not urgent: R7's CLI constructs the
router with its policy.
